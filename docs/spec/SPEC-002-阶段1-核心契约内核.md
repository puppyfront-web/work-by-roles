# SPEC-002 · 阶段1 · V0.1 核心契约内核

> 前置：阶段0 完成。目标版本：0.1.0。本阶段产物为项目根基，模型定版后长期不改。

## 1. RoleContract 契约模型（最终版）`wbr/core/contract/models.py`

Pydantic V2 全强类型，可 JSON 序列化、可哈希定版、可 Diff。

```python
class RoleType(StrEnum): COORDINATOR / EXPERT / VERIFIER

class RoleIdentity:   role_id: str(正则^[a-z][a-z0-9_]{2,63}$) / name / role_type / description
class SopStep:        step_id / title / instruction / expected_output
class Sop:            steps: list[SopStep] (min=1，step_id 唯一)
class ForbiddenRule:  behaviors: list[str]    # 禁止行为（自然语言规则）
                      domains: list[str]      # 禁止回答域
class OutputSpec:     schema: dict            # JSON Schema 子集(D-08)
                      strict: bool = True     # 违规即拦截
                      examples: list[dict]
class EvidenceSpec:   required: bool / citation_format: str / min_citations: int>=0
class ToolPolicy:     whitelist: list[str] / deny_by_default: bool = True
class MemoryPermissions:
                      read_layers: list[MemoryLayer]
                      write_layers: list[MemoryLayer]   # GLOBAL_SHARED 写权限必须显式声明
class TokenQuota:     max_prompt_tokens / max_completion_tokens / max_turn_tokens（均 >0）
class ReviewCriteria: # Verifier 专用；role_type!=VERIFIER 时必须为空（模型级校验）
                      dimensions: list[ReviewDimension]   # name/description/weight(0,1]/pass_threshold(0,1]
                      overall_pass_threshold: float(0,1]

class ContractMeta:   version: str(semver) / content_hash: str(64hex) / created_at / updated_at / changelog: list[str]

class RoleContract:
    identity / sop / forbidden / output_spec / evidence_spec
    tool_policy / memory_permissions / token_quota
    review_criteria: ReviewCriteria|None
    meta: ContractMeta
    model_config = ConfigDict(frozen=False, validate_assignment=True)
```

关键行为：
- `RoleContract.build(...)` 工厂：接收各子模型，自动计算 `content_hash`（D-09 canonical JSON，排除 meta 内 hash 自身与时间戳字段）。
- `to_json() / from_json()` 往返无损；`save(path)/load(path)`。
- `with_changes(**kw)`：派生新版本（copy-on-write，version 可自动 bump，重算 hash）。
- 跨字段校验：Verifier 必须有 review_criteria；Coordinator 不得有；expert 可无。whitelist 空且 deny_by_default ⇒ 完全禁用工具。

## 2. 契约编译器 `wbr/core/contract/compiler.py`

```python
CompiledPrompt: system_prompt: str / user_block: str / sections: dict[str,str] / contract_hash / trace_id
ContractCompiler().compile(contract, user_input, *, evidence: list[str]|None, history: list|None) -> CompiledPrompt
```
固定段序（缺省段跳过）：`safety_guard_header → role_contract_body → output_constraints → forbidden_constraints → evidence_spec`，尾接隔离的用户输入块（`USER_INPUT_OPEN/CLOSE` 包裹，D-14 常量）。
- 安全护栏头为固定文本：声明规则优先级（系统规则 > 历史内容 > 用户输入 > 外部内容）、禁止指令覆盖。
- 编译为纯函数：同输入同输出（含 trace_id 除外）；用户输入中出现的边界标记必须先转义，防伪造边界逃逸。

## 3. 契约版本 Diff 引擎 `wbr/core/contract/diff.py`

```python
ChangeType: ADDED / REMOVED / MODIFIED
ChangePath 分类: FIELD / RULE / SCHEMA / FORBIDDEN / POLICY / META
ContractChange: path / change_type / category / old / new / severity(LOW/MEDIUM/HIGH)
DiffReport: contract_id / from_version / to_version / changes / has_breaking(HIGH 存在)
ContractDiffEngine.diff(old, new) -> DiffReport    # 递归字段级对比，列表按身份键对齐(step_id/citation等)
```
- category 判定：`sop/identity`→RULE，`output_spec`→SCHEMA，`forbidden`→FORBIDDEN，`tool_policy/memory_permissions/token_quota`→POLICY，其余→FIELD。
- severity：FORBIDDEN 放宽、SCHEMA 缩减 required、权限扩大 = HIGH。

## 4. 基础审计模型 `wbr/core/audit/models.py` + `trail.py`

```python
AuditEventType(StrEnum): CONTRACT_COMPILED / EXPERT_STARTED / EXPERT_COMPLETED / EXPERT_FAILED
                        / SCHEMA_VIOLATION / FORBIDDEN_VIOLATION / VERIFIER_VERDICT / REVIEW_COMPLETED
                        / MEMORY_ACCESS / TOOL_CALL / TOKEN_RECORD / SESSION_STARTED
AuditEvent(强类型): event_id(uuid) / event_type / trace_id / ts / role_id? / payload(dict)
RoleBehaviorRecord: role_id / action / input_digest / output_digest / violations / ts   # 内容存摘要，全文外置
TraceNode / TraceTree: 按 trace_id 聚合事件形成链路（parent=review session）
AuditTrail: append(event) / events_for(trace_id) / to_json()
```

## 5. 四层记忆 `wbr/core/memory/`

```python
MemoryRecord: key / value(JSON-able) / layer / role_id? / session_id? / ts / ttl?
MemoryStore(Protocol): get/set/delete/keys/append(list 语义)/clear
InMemoryMemoryStore: 线程安全(RLock)实现，按 (layer, scope) 命名空间隔离
MemoryHub:
    __init__(store: MemoryStore, audit: AuditTrail|None)
    read(layer, role_id, session_id, key, *, contract: RoleContract) -> Any
    write(layer, ..., value, *, contract) -> None
    # 每次访问先校验 contract.memory_permissions，越权抛 MemoryPermissionDeniedError 并写 MEMORY_ACCESS 审计
    # GLOBAL_SHARED 写必须显式授权（即使出现在 write_layers 也要求 allow_global_write=True 才放行）
    scope 规则：ROLE_STATIC→(layer,role)  ROLE_SESSION→(layer,role,session)  TASK_SCRATCH→(layer,session)  GLOBAL_SHARED→(layer,"__global__")
```

## 6. 最简会审流程（纯 Core，无框架）`wbr/core/orchestration/`

```python
ModelInvoker(Protocol): invoke(request: ModelRequest) -> ModelResponse
ModelRequest: role_contract / compiled_prompt / trace_id / memory_snapshot: dict
ModelResponse: text / usage: TokenUsage(prompt, completion) / raw: Any|None
TokenUsage: prompt_tokens / completion_tokens  (合计属性)

ExpertOutcome: role_id / contract_hash / status(PENDING/RUNNING/COMPLETED/FAILED) / output: dict|None
             / raw_text / violations: list[Violation] / error / duration_ms / usage
Violation: kind(SCHEMA|FORBIDDEN) / detail / path?
Verdict: pass_(bool) / scores: dict[dim, float] / comments / judge_role_id
ReviewSession(编排入口):
    __init__(*, coordinator_contract, expert_contracts: list, verifier_contract,
             invoker: ModelInvoker, memory: MemoryHub|None, audit: AuditTrail|None,
             max_workers: int|None, token_meter: TokenMeter|None(阶段2 注入))
    run(question, *, context: dict|None) -> ReviewResult
ReviewResult: review_id / trace_id / question / coordinator_plan / expert_outcomes(按 role_id 排序)
            / verifier_verdict / disagreements: list[Disagreement] / final_answer / status / started_at/finished_at
Disagreement: between: [role_a, role_b] / topic / positions
```

流程：Coordinator 产出 plan（JSON：分派给各专家的子问题）→ 专家并行执行（D-05，编译→invoke→schema 校验→禁区检测→违规记录，strict 时 FAILED）→ 汇总提交 Verifier（含全部专家输出+证据引用检查）→ Verifier 按 review_criteria 打分裁决 → 分歧留存：专家结论相互冲突（对同一子问题给出不同 `conclusion` 键值）时记录 Disagreement，**不仲裁抹平** → final_answer 取 Verifier 通过时的综合结论或明确标注"复核未通过"。
